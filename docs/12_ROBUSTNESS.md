Reproduce: `py -3.13 -X utf8 research/scripts/stress_parity.py --repeats 200`.
Evidence: `evidence/STRESS.md` and `evidence/STRESS.json`.

## 1. Bit-exact parity over repeated passes

| Item | Value |
|---|---|
| Instances per pass | 300 |
| Passes | 200 |
| Checks | 60,000 |
| Mismatches | 0 |
| Throughput, 8 threads | about 34,000 instances per second |
| Exit code | 0 |

Agreement is on the full tuple `(verdict, unsafe actions, excursion minutes,
blocking findings)`, not on a summary score. A disagreement exits 1 and prints
the first ten differences with both sides of the comparison.

## 2. Determinism of the reference implementation

Every instance is evaluated twice in the same process and the tuples compared.
Result: identical. The gate is a pure function of the instance; nothing reads a
clock, a locale, a hash seed, or the order of a set iteration that has not been
sorted first.

## 3. Hostile input

Six malformed files are fed to the core: empty, truncated, duplicated node,
negative capacity and quantity, non-ASCII identifiers, and raw control bytes.

| File | Exit code | Panic |
|---|---|---|
| empty | 2 (refuses to run) | no |
| truncated | 0 | no |
| duplicated node | 0 | no |
| absurd values | 0 | no |
| non-ASCII identifiers | 0 | no |
| control bytes | 0 | no |

Two of these used to crash: `truncated` and `garbage` panicked with an
index-out-of-bounds at the parser, found by this harness on its first run. The
parser now uses total accessors (`tok`, `tok_int`, `tok_micro`) that degrade a
malformed line to a zero-valued record. That is the correct behaviour for a
transport format a third party may edit by hand.

## 4. Liveness and memory

A long run finishes inside its timeout, and peak resident memory is measured from
the operating system rather than assumed:

| Item | Value |
|---|---|
| Wall time, 200 passes | about 2.2 s |
| Peak resident | about 10.4 MB |
| Growth across passes | none observed; per-pass allocation is bounded by the instance count |

No thread pool is created per pass; threads are spawned once per pass and joined
inside a scope, so a slow worker cannot deadlock the run. The harness fails on a
timeout rather than hanging.

## 5. What is not covered

- No sanitizer run (ThreadSanitizer, AddressSanitizer) is claimed. The engine is
  data-parallel over read-only instances and writes only to per-thread vectors,
  but that is an argument, not a measurement.
- No 32-bit or ARM build is claimed. Only x86-64 Windows was measured.
- The hostile corpus is six files, chosen for classes of failure rather than
  generated by a coverage-guided fuzzer. A fuzzer campaign is listed in the
  shortcut ledger, not done.
